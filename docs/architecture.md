# Архитектура проекта — EarnIt Kids

## Суть проекта

**EarnIt Kids** — веб-приложение для геймификации детского воспитания через систему виртуальных монет. Родители создают задачи, за выполнение которых дети получают монеты. Монеты можно тратить на товары в виртуальном магазине, созданном родителями.

### Целевая аудитория
- **Родители** (admin) — управляют задачами, магазином, одобряют запросы
- **Дети** (child) — выполняют задачи, отправляют запросы, покупают товары
- **Суперадминистратор** — управляет всеми семьями в системе

## Технологический стек

| Слой | Технология |
|------|------------|
| **Сервер** | Node.js (чистый `http`, без фреймворков) |
| **БД** | PostgreSQL (драйвер `pg`, raw SQL) |
| **Фронтенд** | Vanilla HTML/CSS/JS (серверный рендеринг) |
| **Email** | Mailgun / Nodemailer |
| **Push** | Firebase Cloud Messaging (FCM) через google-auth-library |
| **Контейнеризация** | Docker + docker-compose |
| **Мобильное приложение** | Android (WebView) + iOS (WKWebView) — обёртки |
| **Тестирование** | Node.js test runner + Playwright E2E |
| **Lint** | ESLint + custom lint scripts |
| **Аналитика** | Microsoft Clarity (опционально) |

## Ключевые аспекты

### Веб (фронтенд)

- **Серверный рендеринг** — HTML собирается из 17 компонентов (`views/components/`) на сервере в `viewController.serveIndex()`. Компоненты конкатенируются в фиксированном порядке
- **Шаблонизация** — простая замена плейсхолдеров (`{{APP_VERSION}}`, `{{CLARITY_SCRIPT}}`)
- **Навигация** — SPA-подобная: один HTML, переключение секций через табы (CSS display)
- **36 JS-модулей** — каждый загружается отдельным `<script>`, без бандлера
- **API-взаимодействие** — `fetch()` к `/api/*`, JSON request/response, cookies для auth
- **Адаптивный дизайн** — тёмная тема, CSS-переменные, медиа-запросы для мобильных
- **Pull-to-refresh** — нативное поведение для мобильных устройств
- **Child Switcher** — родитель может переключаться между детьми, UI обновляется динамически

### Бэкенд

- **Без фреймворков** — чистый `http.createServer()`, ручной роутинг через `url.startsWith()`
- **Слоёная архитектура** — Controller → Service → Repository, чёткое разделение ответственности
- **Аутентификация** — cookie-based: email родителя + пароль, magic-link для детей
- **Три роли** — `admin` (родитель), `child` (ребёнок), `super_admin`
- **Push-уведомления** — FCM через Service Account, уведомления о запросах и изменениях
- **Email** — верификация, сброс пароля, magic-link через Mailgun
- **Backup** — автоматическое и ручное резервное копирование БД
- **Brute-force защита** — ограничение попыток логина (5 попыток / 15 мин)

### База данных

- **10 таблиц** — families, children, tasks, shop_items, history, requests, friends, push_tokens, super_admin, migrations
- **Multi-child** — одна семья может иметь нескольких детей, все данные скоупятся по `child_id`
- **Soft delete** — задачи и товары не удаляются физически (`is_deleted = true`)
- **Миграции** — 10 SQL-файлов, application-level миграции через `scripts/migrate.js`
- **Frequency** — JSONB-поле для настройки повторяемости задач/товаров
- **Money tracking** — поле `money_amount` для привязки к реальным деньгам

## Ключевые бизнес-процессы

### 1. Выполнение задачи
```
Ребёнок → отправляет запрос (request, type=earn) → Родитель одобряет →
→ баланс += coins → запись в history → push-уведомление
```

### 2. Покупка в магазине
```
Ребёнок → отправляет запрос (request, type=shop_purchase) → Родитель одобряет →
→ баланс -= price → запись в history → проверка frequency/money limit
```

### 3. Прямое начисление (админ)
```
Родитель → начисляет/списывает монеты напрямую →
→ баланс ± amount → запись в history
```

### 4. Авторизация ребёнка
```
Родитель → получает magic-link в настройках → отправляет ребёнку →
→ Ребёнок переходит по ссылке → cookie устанавливается → доступ к приложению
```
