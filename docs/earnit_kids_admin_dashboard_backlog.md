# EarnIt Kids - Admin Dashboard UX Backlog

## Цель

Переработать текущий Admin Dashboard в Telegram Mini App так, чтобы он был:
- mobile-first;
- компактным по вертикали;
- удобным для просмотра одной рукой;
- без пустых растянутых карточек;
- без горизонтального скролла;
- без технических i18n-ключей;
- с понятной информационной иерархией;
- с 5 фиксированными смысловыми табами.

Главная UX-проблема текущей реализации: почти каждая метрика оформлена как самостоятельная крупная карточка. Из-за этого мало данных занимает несколько экранов. Нужно перейти к модели: **смысловая группа -> одна карточка -> несколько компактных строк/метрик**.

---

# P0 - критические исправления

## 1. Сделать 5 табов Dashboard

Нижняя навигация Dashboard должна содержать ровно 5 табов:

1. Обзор
2. Монеты
3. Награды
4. Задания
5. Активность

### Важно

Не использовать emoji в табах.

Для каждого таба использовать простую монохромную SVG-графику по смыслу:

- Обзор -> gauge / dashboard
- Монеты -> две монеты
- Награды -> подарок
- Задания -> clipboard/checklist
- Активность -> pulse/activity line

### Поведение

- все 5 табов должны помещаться по ширине 320-430 px;
- без горизонтального скролла;
- label в одну строку;
- иконка над label;
- активный таб - primary background + белые icon/text;
- неактивный таб - белый фон + muted icon/text;
- grid: `repeat(5, minmax(0, 1fr))`;
- уменьшать gap/font на экранах до 350 px, но не скрывать tab.

### Acceptance

- 320 px -> видно все 5 табов;
- 375 px -> видно все 5 табов;
- 390 px -> видно все 5 табов;
- 430 px -> видно все 5 табов;
- ни один label не переносится;
- нет horizontal overflow.

---

## 2. Убрать большое пустое пространство из KPI

### Сейчас

KPI-карточки слишком высокие. Даже при значении `—` внутри остаётся много пустого пространства.

### Нужно

Обычная KPI-карточка:
- min-height: 88-96 px;
- padding: 10-12 px;
- label сверху;
- value сразу под label;
- secondary text сразу под value;
- без `justify-content: space-between`, если он растягивает содержимое;
- gap между KPI около 8 px;
- сетка 2 колонки.

### Пример

```text
Активные семьи       i
163
38% от всех
```

Пустое значение `—` не должно увеличивать высоту карточки.

---

## 3. Tooltip `i` не должен быть отдельной секцией страницы

### Сейчас

После tap по `i` отображается большой тёмный блок внутри document flow. Он занимает много высоты и конфликтует с bottom navigation.

### Нужно

Сделать compact popover или небольшой bottom sheet.

Tooltip содержит:
- название метрики;
- что она означает;
- формулу, если нужна;
- простой пример.

### Поведение

- tooltip не увеличивает высоту dashboard;
- одновременно открыт максимум один tooltip;
- tap вне tooltip закрывает его;
- кнопка `×` закрывает;
- bottom navigation его не перекрывает.

---

## 4. Исправить все i18n-ключи

В UI нельзя показывать строки вида:

```text
admin.dashboard.coins.spendEarn.label
admin.dashboard.funnel.completedTask
admin.dashboard.funnel.hasReward
admin.dashboard.sections.parentNeeds
admin.dashboard.parent.catalogUsage.title
admin.dashboard.sections.childNeeds
admin.dashboard.child.activeDays.title
admin.dashboard.units.hours
```

### Нужно

Все ключи должны иметь русский перевод.

Добавить автоматическую проверку:

```regex
/admin\.dashboard\./
```

Если rendered dashboard содержит такой текст, UI-test должен падать.

---

## 5. Bottom navigation не должна перекрывать контент

Если tab bar fixed/sticky снизу, последний элемент каждой страницы должен полностью прокручиваться выше неё.

Добавить нижний padding:

```css
padding-bottom: calc(var(--dashboard-tabs-height) + env(safe-area-inset-bottom) + 12px);
```

Проверить:
- tooltip;
- последнюю metric row;
- последний график;
- последний section.

# P1 - информационная архитектура и плотность

## 6. Обзор - оставить только обзорные KPI

В секции `Обзор` оставить:

- Всего семей
- Активные семьи
- Всего детей
- Активных детей

Не дублировать здесь:
- Монет заработано
- Монет потрачено
- Получено наград
- Выполнено заданий

Эти показатели принадлежат своим табам.

### Ключевые сигналы

Ниже использовать одну compact list-card:

```text
Зарабатывают, но не тратят      43%
активные дети без наград

Время до решения              18 мин
медиана ответа родителя
```

Не делать отдельную карточку под каждый сигнал.

---

## 7. Уменьшить empty state

Различать два состояния.

### Вообще нет зарегистрированных семей

```text
Нет зарегистрированных семей
Показатели появятся после регистрации первой семьи.
```

### Семьи существуют, но нет событий за выбранный период

```text
Нет активности за 30 дней
Попробуйте выбрать другой период.
```

Высота empty-state примерно 76-95 px.

Не показывать огромную пустую карточку.

---

## 8. Монеты - одна compare-card вместо нескольких больших KPI

Верхняя секция:

```text
Экономика монет

Заработано             Потрачено
12 480                 8 320

[progress]
Spend / Earn i                     67%
```

Требования:
- две основные цифры внутри одной card;
- один общий progress bar;
- ratio в той же card;
- tooltip рядом с ratio;
- не делать отдельные большие cards для earned/spent.

---

## 9. Монеты - связанные метрики объединить

В одной list-card:

- Медианный баланс
- До первой награды
- Зарабатывают, но не тратят

Каждая строка:
- title слева;
- optional `i` рядом с title;
- subtitle ниже;
- value справа;
- divider между строками.

Не делать отдельную card для каждой метрики.

---

## 10. Добавить отдельный tab `Награды`

Структура:

### KPI
- Запросов наград
- Выдано наград

### Цены
- Медианная цена
- Цена выбранной награды
- Не состоялись

### Что дети выбирают
Компактный ranked list:
- категория;
- количество выдач;
- процент;
- rank.

`Монеты` отвечает за экономику.
`Награды` отвечает за запросы, выдачу, стоимость и выбор детей.

---

## 11. Задания сделать компактнее

### Верхние KPI
- Выполнено заданий
- Одобрено заданий

Не использовать английское `Approval rate` в русском UI.

### Контент
Одна list-card:
- Используют каталог
- Создают своё
- Монет за задание

---

## 12. Активность - исправить funnel

Пять stages:

1. Зарегистрировались
2. Добавили ребёнка
3. Есть задание
4. Заработали монеты
5. Получили награду

Каждая строка:

```text
Добавили ребёнка              397 · 93%
[progress bar]
```

### Если данных нет

Не рисовать 5 пустых одинаковых progress bars.

Показывать один compact empty state внутри funnel card.

---

## 13. Активность - сократить число визуальных секций

Не делать отдельный большой section на каждые 2-3 метрики.

### Родительский цикл

Одна list-card:
- Время до решения
- Ждут решения
- Семей с pending

### Детский цикл

Одна list-card:
- Активных дней
- Зарабатывают, но не тратят
- Запросили, но не получили

# P2 - графики, spacing, states

## 14. Исправить мобильные графики

### X-axis

На 30-дневном графике не показывать label для каждого дня.

Показывать максимум 5-7 подписей, например:
- 20 июл
- 25 июл
- 30 июл
- 4 авг
- 9 авг
- 14 авг
- 18 авг

Data points сохраняются, скрываются только лишние labels.

### Размер

Plot area около 120-150 px.

Не использовать desktop-height charts.

---

## 15. Ввести единый vertical rhythm

Рекомендуемые значения:

```text
screen horizontal padding: 12-14 px
H1 -> subtitle:            3-4 px
subtitle -> filters:       12 px
filters -> section:        14 px
section title -> content:   8 px
card -> card:               8 px
section -> next section:   16 px
```

Не использовать пустые spacer-блоки для выравнивания.

---

## 16. Разделить Loading / No data / Zero

### Loading
Skeleton.

### No data
`—`

### Реальное нулевое значение
`0`

`0` и `—` не должны означать одно и то же.

---

## 17. Responsive metric rows

Использовать:

```css
grid-template-columns: minmax(0, 1fr) auto;
```

Value:
```css
white-space: nowrap;
```

Metric title:
- максимум 2 строки;
- длинный текст не должен выталкивать value за экран.

Tab labels всегда в одну строку.

---

## 18. Уменьшить визуальное доминирование `i`

Размер:
- list row -> 18x18 px;
- KPI -> максимум 20x20 px.

Кнопка располагается рядом с title, а не отдельной колонкой.

# Ограничения реализации

Не переписывать Dashboard целиком без необходимости.

Предпочтительно переиспользовать существующие:
- API;
- domain models;
- analytics calculations;
- data hooks;
- i18n infrastructure.

Менять:
- layout;
- grouping;
- tabs;
- CSS;
- tooltip behaviour;
- chart config;
- empty/loading state;
- translations.

Не менять формулы аналитики в рамках этой UX-задачи.

Если backend не отдаёт показатель, показывать корректное `—` / no-data, а не придумывать значение.

# Неочевидный UX-инсайт

Не пытаться решить проблему пустого пространства только уменьшением padding.

Основной выигрыш даёт изменение структуры:

**плохо**
```text
[карточка метрики]
[карточка метрики]
[карточка метрики]
```

**хорошо**
```text
[одна смысловая карточка
 ├ метрика
 ├ метрика
 └ метрика]
```

Именно группировка уменьшает длину Dashboard сильнее, чем уменьшение шрифтов или padding.

## Слабое место решения

Слишком агрессивное уплотнение может ухудшить touch UX. Поэтому нельзя:
- уменьшать tap-target интерактивных элементов ниже разумного мобильного размера;
- делать микроскопические tabs;
- превращать dashboard в плотную таблицу;
- скрывать важные показатели в горизонтальные carousel.

Цель - не максимальная плотность, а **больше полезной информации на одном экране без ухудшения читаемости**.
