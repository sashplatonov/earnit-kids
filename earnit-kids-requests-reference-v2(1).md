# AI-задача: исправить UX двух блоков - `Требует внимания` и `Мои заявки`

Исправь **оба блока одновременно**:

1. `Требует внимания`
2. `Мои заявки`

Цель - убрать потерю ширины и лишнюю высоту, сохранить полный текст заданий/наград и использовать разные layout variants там, где UX-сценарии отличаются.

## Обязательный HTML-референс

Используй файл:

`earnit-kids-requests-reference-v2.html`

как **обязательный визуальный и layout reference**.

Внутри него есть два целевых блока:

- `Reference A - Требует внимания`
- `Reference B - Мои заявки`

При реализации обязательно сверяйся с ними.

Ключевые CSS reference:

- `.card`
- `.card-main`
- `.content`
- `.title`
- `.meta`
- `.reward`
- `.attention-actions`
- `.request`
- `.request-side`
- `.status`
- `.time`
- `.cancel`

Не воспринимай HTML как приблизительный пример. Layout этих двух блоков является требованием.

---

# 1. Общая проблема текущего UI

Сейчас в карточках слишком много пространства теряется из-за:

- вложенных визуальных блоков;
- слишком широких action-зон;
- узкой колонки title;
- избыточных padding;
- layout, где secondary controls конкурируют за ширину с primary content.

Главное правило для обоих блоков:

> Название задания или награды является главным контентом и должно получать максимально возможную ширину.

Нельзя жертвовать title ради кнопок, статусов или служебной информации.

---

# 2. Общая структура карточек

Для обоих экранов использовать:

```text
Section
└── List
    ├── Item
    ├── Item
    └── Item
```

Одна сущность = одна визуальная карточка.

Не использовать:

```text
Section Card
└── List Card
    └── Item Card
```

То есть убрать визуальный `card inside card`.

У `Section` и `List` не должно быть:

- отдельного белого background;
- собственного большого border-radius;
- shadow;
- большой рамки;
- большого внутреннего padding.

---

# 3. Общий content layout

Базовая content-зона должна соответствовать reference:

```css
.card-main {
    display: grid;
    grid-template-columns: 44px minmax(0, 1fr);
    gap: 10px;
    align-items: start;
}
```

То есть:

```text
[ icon ] [ content............................. ]
```

Где `content` содержит:

```text
title
metadata
reward
```

Именно content должен получать всё оставшееся пространство.

---

# 4. Title - обязательные правила для обоих блоков

Сверяйся с `.title` из HTML reference.

Title:

- показывается полностью;
- не обрезается;
- не имеет фиксированной ширины;
- получает всё доступное место;
- может занимать 2-4 строки;
- `min-width: 0`;
- `white-space: normal`;
- `overflow: visible`;
- без ellipsis;
- без line clamp.

Не использовать:

```css
white-space: nowrap;
overflow: hidden;
text-overflow: ellipsis;
```

Не использовать:

```css
-webkit-line-clamp
```

для названия задания или награды.

Если текст длинный, лучше увеличить карточку на одну строку, чем скрыть часть названия.

---

# 5. Блок `Требует внимания`

## Текущая проблема

Сейчас layout фактически выглядит примерно так:

```text
[ icon ][ title ~1/3 ][ buttons ~2/3 ]
```

Из-за этого:

- title получает слишком мало ширины;
- каждое слово переносится;
- карточка становится очень высокой;
- кнопки визуально важнее title;
- большая часть ширины занята controls.

Это UX-баг.

---

# 6. `Требует внимания` - сделать как `Reference A`

Найди в:

`earnit-kids-requests-reference-v2.html`

блок:

`Reference A - Требует внимания`

и повтори его layout.

Карточка должна иметь структуру:

```text
Card
├── card-main
│   ├── icon
│   └── content
│       ├── title
│       ├── metadata
│       └── reward
└── attention-actions
    ├── approve
    └── reject
```

То есть **кнопки не находятся справа от title**.

---

# 7. Правильный вид `Требует внимания`

Пример:

```text
┌──────────────────────────────────────┐
│ 🏠  Сделать одно полезное дело по    │
│     дому без напоминаний             │
│     Ребёнок · Заявка на задание      │
│     🪙 +2                            │
│                                      │
│     [✓ Одобрить] [× Отклонить]       │
└──────────────────────────────────────┘
```

Ключевой принцип:

```text
content row
actions row
```

а не:

```text
content column | actions column
```

---

# 8. `Требует внимания` - actions

Сверяйся с `.attention-actions` из reference:

```css
.attention-actions {
    margin-top: 10px;
    margin-left: 54px;
    display: grid;
    grid-template-columns: 1fr 1fr;
    gap: 8px;
}
```

Логика:

```text
             [✓ Одобрить] [× Отклонить]
```

Кнопки:

- идут под content;
- две в одной строке;
- одинаковой или близкой ширины;
- высота примерно `36-40px`;
- gap около `8px`;
- не участвуют в расчёте ширины title.

Критическое правило:

> `Одобрить` и `Отклонить` не должны отнимать горизонтальное место у title.

---

# 9. `Требует внимания` - не делать

Запрещён layout:

```text
┌────────────────────────────────────┐
│ 🏠 Сделать... │ ✓ Одобрить        │
│    одно...    │ × Отклонить       │
└────────────────────────────────────┘
```

если title из-за этого получает узкую колонку.

Запрещено:

- оставлять buttons справа от title;
- давать actions 40-60% ширины строки;
- уменьшать font-size title ради buttons;
- обрезать title;
- делать вертикальный список кнопок справа.

---

# 10. `Требует внимания` - metadata

После title компактно показать:

```text
Ребёнок · Заявка на задание
🪙 +2
```

Не создавать отдельные большие блоки для:

- типа заявки;
- ребёнка;
- монет.

Secondary information должна быть компактной.

---

# 11. Блок `Мои заявки`

`Мои заявки` тоже нужно привести к reference и проверить полностью.

Используй:

`Reference B - Мои заявки`

из файла:

`earnit-kids-requests-reference-v2.html`

---

# 12. `Мои заявки` - целевой layout

Здесь допустима компактная правая колонка, потому что status/actions меньше по размеру и не являются двумя большими primary buttons.

Структура:

```text
[ icon ] [ content................ ] [ compact side ]
```

Пример:

```text
┌──────────────────────────────────────┐
│ 🏠  Сделать одно полезное дело по    │
│     дому без напоминаний    Ожидает  │
│     🏠 Дом и порядок        сегодня  │
│     🪙 +2                  Отменить  │
└──────────────────────────────────────┘
```

Но только если text column остаётся нормальной ширины.

---

# 13. `Мои заявки` - использовать `.request`

Ориентируйся на reference:

```css
.request {
    display: grid;
    grid-template-columns: 44px minmax(0, 1fr) auto;
    gap: 10px;
    align-items: start;
}
```

То есть:

```text
44px       flexible                 auto
icon    |  content               | side
```

Главное:

`content` должен оставаться flexible и получать основную ширину.

---

# 14. `Мои заявки` - правая колонка

Сверяйся с:

```css
.request-side
.status
.time
.cancel
```

Правая колонка содержит:

```text
Ожидает
сегодня, 07:27
Отменить
```

Она должна быть:

- компактной;
- только по ширине содержимого;
- без фиксированной большой ширины;
- без большого пустого пространства.

Не задавать ей:

```css
width: 40%;
```

или похожие значения.

---

# 15. `Мои заявки` - главное правило ширины

Если side-column начинает слишком сильно сжимать title, переключить layout:

```text
[ icon ][ content........................ ]
        [ status · time ]
        [ Отменить ]
```

То есть на узкой ширине side-group переносится вниз.

Пример:

```text
┌──────────────────────────────────────┐
│ 🏠  Сделать одно полезное дело по    │
│     дому без напоминаний             │
│     🏠 Дом и порядок · 🪙 +2         │
│                                      │
│     Ожидает · сегодня, 07:27         │
│     [Отменить]                       │
└──────────────────────────────────────┘
```

---

# 16. Responsive для `Мои заявки`

Сделай responsive behavior по доступной ширине, а не только по конкретной модели телефона.

Когда content становится слишком узким:

- `.request-side` переносится ниже content;
- title остаётся широким;
- не включается ellipsis;
- horizontal scrolling не появляется.

---

# 17. Разница между двумя блоками обязательна

Не пытайся использовать один и тот же grid layout для обоих экранов.

Это важное требование.

## `Требует внимания`

```text
icon + content
actions below
```

## `Мои заявки`

```text
icon + content + compact side
```

с responsive переносом side вниз.

---

# 18. Общий компонент

Можно и желательно сохранить общий reusable component.

Например:

```text
CompactRequestCard
```

с variants:

```text
variant="attention"
```

и:

```text
variant="my-request"
```

Общими оставить:

- card shell;
- icon;
- title;
- metadata;
- reward;
- typography;
- spacing.

Различными:

- placement actions;
- placement status;
- responsive behavior.

Не дублировать весь component только ради layout.

---

# 19. Компактность

Ориентиры из reference:

```text
card padding: 10-12px
gap: 8-10px
icon: 40-44px
button height: 36-40px
```

Не нужно копировать числа пиксель-в-пиксель, если design system использует свои tokens.

Но визуальная плотность должна быть такой же.

---

# 20. Не создавать лишнюю высоту

Убрать:

- слишком большие margin между title и metadata;
- большие пустые зоны над buttons;
- отдельные containers вокруг status;
- большие wrapper padding.

Secondary information должна занимать минимум пространства.

---

# 21. Проверка длинных title

Обязательно протестировать минимум такие случаи:

```text
Сделать одно полезное дело по дому без напоминаний
```

```text
Выбрать семейный фильм на вечер и приготовить место для просмотра
```

```text
Собрать вещи на завтра вместе со списком
```

Они должны читаться полностью и иметь естественные переносы.

---

# 22. Acceptance criteria - `Требует внимания`

Задача по этому блоку выполнена, если:

1. Title занимает почти всю ширину справа от icon.
2. Buttons не находятся справа от title.
3. `Одобрить` и `Отклонить` идут отдельной строкой ниже.
4. Обычный длинный title занимает примерно 2-3 строки, а не 5-8 узких строк.
5. Title не обрезается.
6. Metadata компактная.
7. Reward компактный.
8. Нет nested cards.
9. Нет horizontal scroll.
10. Карточка визуально соответствует `Reference A`.

---

# 23. Acceptance criteria - `Мои заявки`

Задача по этому блоку выполнена, если:

1. Title имеет нормальную широкую колонку.
2. Status занимает только необходимую ширину.
3. Timestamp компактный.
4. `Отменить` не создаёт огромную правую колонку.
5. На узком экране side переносится вниз.
6. Title не обрезается.
7. Нет nested cards.
8. Нет horizontal scroll.
9. Карточка остаётся компактной.
10. UI соответствует `Reference B`.

---

# 24. Проверить оба блока после реализации

После изменений сделай визуальное сравнение с:

`earnit-kids-requests-reference-v2.html`

и отдельно проверь:

### Reference A

`Требует внимания`

### Reference B

`Мои заявки`

Не считать задачу завершённой, если исправлен только один из двух блоков.

---

# Definition of Done

Задача завершена только когда **оба блока одновременно** соответствуют следующим принципам:

## `Требует внимания`

```text
┌──────────────────────────────────────┐
│ icon  full-width content             │
│       full title                     │
│       metadata                       │
│       reward                         │
│       [approve] [reject]             │
└──────────────────────────────────────┘
```

## `Мои заявки`

```text
┌──────────────────────────────────────┐
│ icon  full-width content    status   │
│       full title            time     │
│       metadata              cancel   │
│       reward                         │
└──────────────────────────────────────┘
```

или на узком экране:

```text
┌──────────────────────────────────────┐
│ icon  full-width content             │
│       full title                     │
│       metadata                       │
│       reward                         │
│       status · time                  │
│       cancel                         │
└──────────────────────────────────────┘
```

Главное правило:

> Primary content получает ширину первым. Controls и secondary information адаптируются под него, а не наоборот.
